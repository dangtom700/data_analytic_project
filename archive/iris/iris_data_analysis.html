def extract_result(y_test, y_pred):
    # Compute Confusion Matrix
    conf_matrix = confusion_matrix(y_test, y_pred)

    # Accuracy Score
    accuracy = accuracy_score(y_test, y_pred)

    # Sensitivity (Recall Macro-Averaged)
    sensitivity = recall_score(y_test, y_pred, average='macro')

    # F1 Score Calculation
    f1 = f1_score(y_test, y_pred, average='macro')

    # Precision Score Calculation with Safe Division Handling
    precision = precision_score(y_test, y_pred, average='macro', zero_division=0)

    # Specificity Calculation (Mean of Per-Class Specificity)
    specificity_list = []
    for i in range(len(conf_matrix)):
        tn = conf_matrix.sum() - (conf_matrix[i, :].sum() + conf_matrix[:, i].sum() - conf_matrix[i, i])
        fp = conf_matrix[:, i].sum() - conf_matrix[i, i]
        specificity = tn / (tn + fp) if (tn + fp) > 0 else 0
        specificity_list.append(specificity)
    
    specificity = np.mean(specificity_list) if specificity_list else 0
    
    return {
        "accuracy": accuracy,
        "sensitivity": sensitivity,
        "specificity": specificity,
        "precision": precision,
        "f1_score": f1,
        "overall": (accuracy + sensitivity + specificity + precision + f1) / 5
    }

def create_report(y_test, y_pred, class_labels, plot_title):
    # Compute Confusion Matrix
    conf_matrix = confusion_matrix(y_test, y_pred)

    # Plot Confusion Matrix
    plt.figure(figsize=(8, 6))
    sns.heatmap(conf_matrix, annot=True, fmt="d", cmap="Blues", 
                xticklabels=class_labels if len(class_labels) > 0 else range(len(conf_matrix)), 
                yticklabels=class_labels if len(class_labels) > 0 else range(len(conf_matrix)))
    plt.xlabel("Predicted Label")
    plt.ylabel("True Label")
    plt.title(plot_title)
    plt.show()

    # Accuracy Score
    accuracy = accuracy_score(y_test, y_pred)

    # Sensitivity (Recall Macro-Averaged)
    sensitivity = recall_score(y_test, y_pred, average='macro')

    # F1 Score Calculation
    f1 = f1_score(y_test, y_pred, average='macro')

    # Precision Score Calculation
    precision = precision_score(y_test, y_pred, average='macro')

    # Specificity Calculation
    specificity_list = []
    for i in range(len(conf_matrix)):
        tn = conf_matrix.sum() - (conf_matrix[i, :].sum() + conf_matrix[:, i].sum() - conf_matrix[i, i])
        fp = conf_matrix[:, i].sum() - conf_matrix[i, i]
        specificity = tn / (tn + fp) if (tn + fp) > 0 else 0
        specificity_list.append(specificity)
    specificity = np.mean(specificity_list)

    # Print Results
    print(f"Accuracy: {accuracy:.4f}")
    print(f"Sensitivity (Macro Recall): {sensitivity:.4f}")
    print(f"Specificity (Macro Specificity): {specificity:.4f}")
    print(f"Precision (Macro): {precision:.4f}")
    print(f"F1 Score: {f1:.4f}")
    print("\nClassification Report:\n", classification_report(y_test, y_pred))

Get and visualize evaluation¶

The most important ideas of evaluating the model is using confusion matrix. It's a matrix that evaluate based on the actual true, false and the predicted true, false. In a higher dimensional analysis or when working with multiple models, the results is more focus on the predicted and the actual items in the classified categories, complete matched.

The first function is used to extract evaluation data from a training section, while the second function is used to visulize the data with heat map, and classification report. The classification report has some key information to capture:

  • Accuracy: the proportion of all classifications that were correct, whether positive or negative. $$\frac{\text{correct classification}}{\text{total classification}}$$
  • Recall: the proportion of all actual positives that were classified correctly as positives. $$\frac{\text{correctly classified actual positives}}{\text{all actual positives}}$$
  • False positve rate (false alarm): the proportion of all actual negatives that were classified incorrectly as positives $$\frac{\text{incorrectly classified actual negatives}}{\text{all actual negatives}}$$
  • Precision: the proportion of all the model's positive classifications that are actually positive $$\frac{\text{correctly classified actual positves}}{\text{everything classified as positive}}$$
  • F1 score: harmonic mean of precision and recall $$2*\frac{\text{precision}*\text{recall}}{\text{precision}+\text{recall}}$$

Get the first glimpse of the data¶

The first step of data analysis is to take a look at the raw data. The goal is to the see the structure of the data, especially the headers. So that, the classification can be derived. In this case, the goal of the classification is the iris species, such as Iris-setosa, Iris-versicolor, Iris-virginica, based on sepal length, sepal width, petal length, petal width.

The second goal is taking a glimpse of the data is to detect the missing values or wrong formatted data. This is a big problem in training model. Dirty data damage the performance of model. In this case, all the values are filled and there is no wrong formatted data.

The next step to encode the targets with labels. In most case, the classification is trying to detect a non-numeric categories, so it is safe to encode the targets before putting in classification models. The dataset is then split into training and testing dataset in 80-20 portion after random shuffle. Data normalization is also important, to prevent one feature overwhelms the other parameters and misleads the final result

KNN¶

The K-Nearest Neighbors (KNN) model is a popular supervised learning algorithm used for classification tasks. It works by finding the k most similar instances to a new, unseen data point and using their characteristics as features to make predictions.

Mechanism:

  1. Input dataset: A set of examples (training data) with their respective features.
  2. Nearest neighbors: Find the k nearest neighbors to the input data point in the feature space.
  3. Decision rule: Use the features of these k nearest neighbors to make a prediction about the new data point.

Pros:

  1. Simple to implement: KNN is one of the simplest machine learning algorithms to understand and implement, making it suitable for beginners.
  2. Innocuous: KNN has no risk of overfitting, as its decision rule is based on majority voting among k nearest neighbors.
  3. Interpretable results: The number of nearest neighbors (k) can be easily tuned to balance accuracy and computational cost.
  4. Flexible: KNN can handle high-dimensional data with a large number of features.

Cons:

  1. Sensitive to the value of k: Choosing an appropriate value for k is crucial, as it can significantly impact the model's performance.
  2. Vulnerability to overfitting: If k is too small or too large, the model may not generalize well to new data or may overfit to the noise in the training dataset.
  3. Limited robustness: KNN models can be sensitive to outliers and changes in the feature space, which may lead to suboptimal performance.

Example Use Cases:

  1. Image classification: KNN can be used for image classification tasks where the number of classes is relatively small (e.g., 10-100).
  2. Text classification: KNN can be applied to text data with a small number of classes.
  3. Regression analysis: KNN can be used for regression problems with a relatively small number of features.

Tuning Parameters:

To optimize the performance of the KNN model, tune the following parameters:

  • k (number of nearest neighbors): This is typically set to 1 or more based on the problem size and data characteristics.
  • Metric: Use the Euclidean distance or Mahalanobis distance as the metric for finding nearest neighbors.
  • Weighting: Assign weights to different features using techniques like ranking, importance scoring, or hybrid methods.

Decision Tree¶

The Decision Tree model is a popular supervised learning algorithm used for classification tasks. It works by recursively partitioning the data into smaller subsets based on the features, using a
series of simple if-then rules to make predictions.

Mechanism:

  1. Root node: The root node represents the entire dataset and contains the first feature.
  2. Feature splitting: A split occurs when the value of one feature exceeds a certain threshold or falls within a specific range. This determines which branches to take next.
  3. Decision nodes: Decision nodes (also called leaf nodes) represent individual features with their respective values. If the value matches the threshold, the prediction is made; otherwise,
    it falls into a recursive call.
  4. Leaf nodes: Leaf nodes are decisions that have no branching or splitting. The predictions from these nodes are combined using majority voting to make final classifications.

Pros:

  1. Easy to interpret: Decision Trees are often visual representations of relationships between features and target variables, making it easy to understand the model's logic.
  2. Simple to implement: Decision Trees have a relatively simple algorithm and can be implemented using various programming languages and libraries.
  3. Handling missing values: Decision Trees can handle missing values in the data by inserting them into the tree structure.
  4. Robust to outliers: Decision Trees are resistant to outliers, as they avoid creating unnecessary splits or branches.

Cons:

  1. Overfitting risk: If the model is too complex or has too many features, it may overfit the training data, leading to poor generalization performance on new data.
  2. Not suitable for high-dimensional data: Decision Trees can suffer from high computational complexity and memory usage in high-dimensional datasets.
  3. Sensitive to feature correlations: The tree's structure is sensitive to feature correlations, which can lead to biased models if not properly addressed.

Example Use Cases:

  1. Credit risk assessment: Decision Trees are commonly used for credit risk assessment due to their ability to handle missing values and correlations between features.
  2. Customer churn prediction: Decision Trees can be applied to predict customer churn by identifying the factors that contribute to the likelihood of a customer leaving the company.
  3. Medical diagnosis: Decision Trees can be used in medical diagnosis to identify patients with specific diseases based on their symptoms, medical history, and test results.

Tuning Parameters:

To optimize the performance of the Decision Tree model, tune the following parameters:

  • Maximum depth: Adjusts the number of recursive calls; a higher value may lead to overfitting.
  • Minimum sample size: Ensures that at least a certain proportion of samples are present in each node.
  • Threshold for split: Controls when a feature is split based on a specific condition (e.g., greater than or equal to).
  • Maximum depth parameter: Adjusts the maximum number of recursive calls.

Best Practices:

  1. Use a good initial random forest with fewer trees (5-10) and tune hyperparameters.
  2. Regularly prune branches that are not contributing to the decision tree's performance.
  3. Monitor model complexity using metrics like Gini impurity or Entropy.
  4. Visualize the decision tree to understand its structure and interpretations.

Random Forest¶

The Random Forest model is an ensemble learning algorithm that combines multiple decision trees to improve the accuracy, robustness, and interpretability of predictions. It's particularly useful
for classification tasks with high-dimensional data or complex relationships between features.

Mechanism:

  1. Bootstrap sampling: A random sample of the data is drawn from each tree in the ensemble.
  2. Tree construction: Each tree in the ensemble uses a specific feature to split the data into two subsets, based on its predicted probability.
  3. Prediction and scoring: The predictions from each tree are combined using majority voting (i.e., taking the class with the highest probability).
  4. Feature importance: The relative importance of each feature in contributing to the decision for each tree is estimated.

Conditions Needed for Random Forest Performance:

  1. High-dimensional data: Random Forest can handle high-dimensional data by selecting a subset of features to consider at each node.
  2. Complex relationships between features: Random Forest's ability to handle complex relationships between features comes from its use of multiple decision trees and the bootstrap sampling technique.
  3. Noisy or missing data: Random Forest can handle noisy or missing data using techniques like bagging, bootstrapping, or imputation.
  4. Overfitting prevention: Random Forest's ensemble nature helps prevent overfitting by reducing the impact of individual tree performance on the overall model.
  5. Feature selection: Choosing relevant features is crucial for Random Forest; feature importance can be estimated using metrics like Gini impurity or Permutation Feature Importance.

Key Parameters:

  1. Number of trees (n_estimators): Increasing this value generally improves performance but may lead to overfitting.
  2. Bootstrap sampling rate (100% vs. 80%): Higher rates increase the chances of capturing complex relationships, but also reduce accuracy for simple datasets.
  3. Maximum depth (max_depth): Setting a maximum depth can prevent overfitting but reduces the model's interpretability.

Tuning Parameters:

To optimize Random Forest performance, tune the following parameters:

  • n_estimators (number of trees): Adjust this value based on dataset size and complexity.
  • bootstrap_rate: Set between 0.1% to 80%, depending on the dataset type and desired tradeoff between accuracy and interpretability.
  • max_depth: Set a maximum depth to prevent overfitting, or leave it as is for more interpretable models.

Best Practices:

  1. Use Bagging instead of Bootstrap if you're unsure about the relationship between features and want a more accurate estimate.
  2. Use a smaller number of trees (5-10) and gradually increase until you reach optimal performance.
  3. Regularly monitor feature importance using metrics like Permutation Feature Importance or SHAP values to understand which features contribute most to predictions.

Support Vector Machine¶

The Support Vector Machine (SVM) is a supervised learning algorithm used for classification and regression tasks. It's particularly useful when the number of features is high or the relationships
between features are complex.

Mechanism:

  1. Linear or non-linear kernel selection: The SVM can use linear or non-linear kernels to map the data into a higher-dimensional space where complex relationships become apparent.
  2. Feature scaling and normalization: The dataset is often scaled and normalized to ensure that all features have similar magnitudes, which helps the algorithm to find optimal hyperparameters.
  3. Hyperparameter tuning: SVMs typically require tuning of several hyperparameters, such as the regularization parameter C, kernel type (linear or radial basis function), and number of iterations.

Pros:

  1. Handling high-dimensional data: SVM can handle datasets with thousands of features by using a non-linear kernel to map the data into a lower-dimensional space.
  2. Robustness against noise and outliers: SVM is robust to noisy or outlier-prone data as it uses kernels, which allows it to identify patterns and relationships that are not present in the
    original data.
  3. Handling complex relationships between features: SVM can model non-linear relationships between features by using a kernel that maps the data into a higher-dimensional space.

Cons:

  1. Computational complexity: SVMs can be computationally expensive, especially when dealing with large datasets or complex kernels.
  2. Overfitting risk: SVMs are prone to overfitting if not tuned properly, which can lead to poor generalization performance on unseen data.
  3. Interpretability limitations: Due to the nature of kernel-based models, it can be challenging to interpret the results and understand the relationships between features.

Working Conditions for SVM:

  1. Feature types: SVM can handle both numeric and categorical feature types. However, when dealing with categorical data, the SVM might require additional preprocessing steps, such as one-hot encoding.
  2. Kernel selection: The choice of kernel type (linear or radial basis function) significantly affects the performance of the model. Linear kernels are suitable for datasets with a small number of features and numeric features, while radial basis functions are better suited for datasets with many features or non-linear relationships.
  3. Hyperparameter tuning: SVMs require tuning of several hyperparameters, including regularization parameter C, kernel type, and number of iterations.

Tuning Parameters:

  1. Regularization parameter C: This hyperparameter controls the trade-off between the margin and the smoothness of the model. Increasing C can improve the generalization performance but may
    lead to overfitting.
  2. Kernel type (linear or radial basis function): Choosing the right kernel type depends on the dataset characteristics, such as the number of features and the relationships between them.
  3. Number of iterations: The number of iterations controls the convergence speed of the algorithm.

Best Practices:

  1. Use a robust initializer: Selecting an appropriate initialization method can significantly impact the performance of the model.
  2. Regularly monitor feature importance: Use techniques like SHAP values or LIME to understand which features contribute most to predictions and improve the model's interpretability.
  3. Combine with other models: Combining SVM with other models, such as Random Forest or Gradient Boosting, can lead to more accurate results and better overall performance.
